# Hy-MT2 Chrome 무서버 실행 검증

## 결론

Hy-MT2는 Chrome 안에서 실제로 구동됐다. 별도 추론 서버 없이 `@wllama/wllama 3.5.1`과 WebGPU로 GGUF 모델의 33개 레이어 전부를 GPU에 올렸고, 서버 포트를 닫은 뒤에도 두 번째 번역을 완료했다.

이 프로젝트는 더 이상 “브라우저 로컬 추론이 될지 모르는 장난감” 단계는 아니다. 다만 첫 방문에 1.13GB를 받아야 하는 설치 비용과 저사양 기기 대응은 제품의 핵심 난제로 남는다.

## 실제 환경

- Chrome 150, Windows
- `crossOriginIsolated=true`
- WebGPU 사용 가능
- 16개 논리 CPU, wllama 멀티스레드 4개
- Hy-MT2 1.79B, Q4_K_M, GGUF 1.05GiB
- WebGPU 33/33 레이어 오프로딩
- GPU 모델 버퍼 1,075.74MiB
- GPU KV 버퍼 128MiB
- GPU 계산 버퍼 25.01MiB

## 실행 결과

| 단계 | 입력 | 출력 | 시간 | 판정 |
|---|---|---|---:|---|
| 최초 로드 및 번역 | `분위기만 싸해졌어.` | `The atmosphere just became cooler.` | 모델 14,950ms + 생성 374ms | 통과 |
| 서버 종료 후 재번역 | `아무리 바빠도 밥은 먹고 다녀.` | `No matter how busy you are, you still need to eat and go around.` | 생성 465ms | 통과 |

두 번째 실행 전 `127.0.0.1:8191` 포트가 닫힌 것을 확인했다. 이미 열린 탭은 모델을 다시 받거나 외부 추론 API를 호출하지 않고 번역했다.

## 품질 관문과 함께 본 결과

동일한 24문장 수동 의미 평가에서 Hy-MT2는 40/48점(83.3%), Chrome 내장 Translator는 25/48점(52.1%)이었다. Hy-MT2의 중대 의미 오류는 2건, Chrome은 7건이었다. 이 평가는 독립적인 블라인드 패널이 아닌 1차 수동 평가이므로 출시 전 더 큰 블라인드 평가가 필요하다.

## 정확한 제품 정의

“서버 없음”은 웹 호스팅조차 없다는 뜻이 아니다.

- 정적 사이트와 모델 파일을 전달하는 호스팅은 필요하다.
- 번역문을 받고 모델을 실행하는 추론 서버는 필요하지 않다.
- 최초 1회 모델을 받은 뒤 번역은 사용자 Chrome에서 처리된다.
- 따라서 운영비는 GPU 서버가 아니라 정적 파일 전송량이 중심이다.

## 남은 위험

1. 첫 방문 1.13GB 다운로드는 모바일·저속 회선에서 큰 이탈 요인이다.
2. 이번 장비는 NVIDIA Lovelace GPU와 약 2GiB의 사용 가능 WebGPU 메모리를 제공했다. iGPU와 저사양 장비의 성공률은 아직 모른다.
3. 페이지 새로고침 후 Chrome 영구 캐시 재사용은 성공한 오프라인 실행 이후 자동화 연결이 끊겨 재검사하지 못했다.
4. Safari와 Firefox는 현재 제품 범위에서 제외하는 편이 안전하다.
5. 모델·wllama 라이선스, 정적 호스팅의 대역폭 비용, 업데이트 시 캐시 마이그레이션 정책을 출시 전에 확정해야 한다.

## 제품 비전

포지셔닝은 “프라이버시를 믿어 달라는 번역기”가 아니라 **문장을 서버로 보내지 않는 Chrome 번역기**여야 한다.

- 방문 즉시 짧은 데모는 가벼운 경로로 제공한다.
- 사용자가 고품질 로컬 모드를 선택하면 모델 크기와 저장 공간을 정확히 고지한다.
- 설치 후에는 Kagi처럼 무료 트래픽을 막을 이유가 없고, Brave처럼 특정 브라우저 제품의 내장 기능에 종속되지 않는다.
- 핵심 차별점은 Hy-MT2의 한국어 품질, 로컬 처리의 검증 가능성, 계정·로그·서버 보관이 없는 단순한 신뢰 모델이다.

다음 제품 관문은 기능 추가가 아니라 저사양 Chrome 성공률과 첫 실행 이탈률이다.
